* Database constraints (UNIQUE indexes, primary keys, foreign keys).
* Form validation logic.
* Required fields.

## 2. Improve error handling

Currently, when an error occurs, the application does not clearly explain what happened.

I want every failed operation to display a meaningful error message.

Instead of generic messages like:

* "Something went wrong"
* "Failed to save"

display the real reason.

Examples:

* "Fleet Number is required."
* "Expense Date is invalid."
* "Driver Name cannot be empty."
* "Database connection failed."
* "A duplicate record already exists."
* "Unable to save because the Freight does not exist."
* "The selected Fleet Number is invalid."

The message should help the user understand exactly what needs to be corrected.
